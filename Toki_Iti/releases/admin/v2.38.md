## Highlights

### Ticket Widgets. Interactive Content, Right Inside the Ticket

#### Your tickets just got a lot more capable
Until now, extra information in a ticket was something you looked at. With Ticket Widgets in the new Ticket UI v2, the tech portal can show live content from any provider, and agents can act on it without leaving the ticket.

A widget can show a list of related items and open the details of one. It can report the progress of an automation as it runs. It can ask an agent for a quick decision, or offer buttons and dropdowns for common actions. Each response replaces the widget in place, so a widget works like a small app inside the ticket.

#### Why we built it
Dynamic Content was designed to display content from a single API. That API had to return every block, so combining content from several systems meant building one API to merge them all.

Ticket Widgets separate those concerns. Each widget has its own provider, and that provider can be an external service or an API you build yourself. Adding a new source of ticket information no longer means reworking an existing integration. Widgets replace Dynamic Content in the same place in the ticket, starting with the tech portal.

### Ticket Timesheet. See When the Work Actually Happened

#### A time-centric view of your ticket's work

Time entries have always lived in the ticket timeline, next to comments. The new **Ticket Timesheet** gives them their own view. It shows only time entries, **grouped by date and ordered by start time**. Each entry shows when the work started and ended, and how long it took. Each day also shows its **total hours**.

The timesheet is laid out in two parts. The list of time entries takes up most of the screen. A side panel on the right, about 20% of the width, breaks down the time worked **by agent**.

#### Why we built it

The timeline records when things were created and changed, and that is the right job for a timeline. But creation time is not the same as work time. An agent might work on a ticket, get pulled onto something else, and log the time a week later. In the timeline, that entry sits at the day it was logged, not the day the work was done.

The timeline also hid the details. An entry showed only an icon, and you had to hover over it to see the start time, end time, and duration. That is a lot of steps just to find out when someone worked on a ticket.

So we kept the timeline as it is and added a view built for the question it can't answer: **when did the work happen?**

#### What it means for you

- **See the work on the day it happened.** Entries are grouped by date and ordered by start time, whenever they were logged.
- **No more hovering.** Start time, end time, and duration are shown on every entry.
- **Daily totals at a glance.** Each day shows the hours spent, so you can see how much time went into the ticket on any given day without adding it up yourself.
- **See who did the work.** The side panel shows hours worked by each agent on the ticket.
- **One click away.** Once time has been logged, the ticket's side panel shows the total time worked under the time spent information. Click it to open the timesheet.
